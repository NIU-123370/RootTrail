# 软件故障调查工作台：项目设计文档

版本：v0.1 / 日期：2026-10-15。

这套文档描述一个基于 REA 的本地软件故障调查工作台。它把具体Bug调查、可人工介入的证据界面和受支持执行环境结合起来。本文档是产品与工程设计，尚未实现软件，也未完成REA或目标应用的运行验证。

## 产品一句话

开发者提交一个 Electron / JavaScript 故障，系统帮助复现、组织证据、接受人工纠正，最终交付可核对的调查结果和可独立运行的测试。

优先场景：“旧版本能导出，新版本失败，帮我查清差异，并留下回归用例。”单版本也可调查，但不能声称确认版本回归。

## 首版明确采用的假设

- macOS Apple Silicon、单机单用户，精确兼容版本待M0验证。
- 用户有源码或可调试构建，已有能启动应用的开发环境。
- 本地Web界面、Fastify API、Node worker；SQLite和本地文件保存状态与证据。
- REA提供已有分析与捕获能力；工作台实现业务验证、人工纠正、持久调查与交付。
- 自动补丁及PR进入P1；多平台、云端团队服务和Webhook后续验证。

## 最重要的验收标准

1. 同一冻结输入与断言，能够区分基线通过、候选业务失败和执行器本身错误。
2. 人工纠正后，相关旧结论进入待复核，原证据和历史仍可查。
3. 中断、重连和重复提交不会静默丢状态或重复执行未知副作用。
4. 导出的用例无需模型或工作台服务也能运行；缺目标程序等前提时明确说明。

## 实施顺序与估算

先用1周左右完成技术可行性验证，再做手动完整链路、Agent介入、恢复与交付、真实试点。完整P0以2位有相关经验的开发者粗估8—10周，需M0后修订；单人2—3周仅适合验证缩减演示，不等于全部P0。

竞争与需求结论均是待验证假设，不声称市场独有。资料核对日期为2026-10-15，官方参考链接位于PRD及架构文档末尾。
